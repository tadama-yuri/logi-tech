# 要件メモ

## 目的

ドライバーと管理者が勤務実績と荷待ち時間を記録し、ドライバー別の稼働状況を確認できる Android 対応アプリを作る。

## 想定利用者

- ドライバー: 自分の勤務実績を入力する
- 管理者: 全体を分析し、ユーザーを管理する

## 画面と MVP 機能

1. ログイン: 試作ではユーザーを選んでアプリに入る。ヘッダーのログアウト操作でログイン画面へ戻る。本番では認証とロール別アクセス制御が必要。
2. データ入力: 勤務開始・終了、休憩・荷待ちの開始と終了をボタンで記録する。従来の手入力にも対応する。未終了の勤務を画面上で通知し、同じドライバー・勤務日の記録がある場合は警告する。保存前に入力内容を確認する。
3. 入力データ確認: 記録一覧を表示し、名前検索、ドライバー、日付範囲、承認状態で絞り込む。管理者は全記録を、ドライバーは自分の記録のみ編集・削除できる。記録は管理者の承認待ちで登録し、承認または理由付き差し戻しを行う。作成・編集・削除・審査の履歴を確認でき、編集後は未承認に戻す。
4. 分析結果: 管理者のみ閲覧可能。総実働、荷待ち、稼働率とドライバー別集計を表示する。
5. ユーザー管理: 管理者のみ画面を閲覧し、ユーザーの追加・削除を行える。本番ではサーバー側のロールと有効状態の管理を追加する。
6. 勤務予定・入力リマインダー: 管理者がドライバーごとに勤務予定日を登録する。予定日の翌日以降、勤務記録がない場合はドライバー本人がアプリを開いたときに画面内で通知する。予定日が過ぎても当日は未入力判定しない。
7. 自動レポート: 管理者のみ、アプリ内の集計値から自動レポートを作成できる。外部AIサービスへデータを送信せず、記録やユーザーを変更しない。

## 集計ルール（試作）

- 拘束時間 = 勤務終了 - 勤務開始。終了が開始より前なら翌日終了として扱う。
- 実働時間 = 拘束時間 - 休憩時間。
- 稼働時間 = 実働時間 - 荷待ち時間。
- 稼働率 = 稼働時間 / 実働時間。実働が 0 の場合は 0% とする。
- 荷待ち時間が実働時間を超える入力は受け付けない。

## データ項目（案）

- 勤務記録: ID、日付、ユーザー ID、開始・終了時刻、休憩分、荷待ち分、メモ、登録日時、承認状態、審査情報
- 変更履歴: 対象記録、勤務者、実行者、操作、変更前後の内容、理由、日時
- 進行中の勤務: ユーザー ID、開始日時、休憩・荷待ちの累計分、進行中の状態。ブラウザー内に保存し、勤務終了時に勤務記録へ確定する。
- ユーザー: ID、表示名、ロール（ドライバー・管理者）

## 非機能・未決事項

- スマートフォン優先のレスポンシブ UI。Android Chrome のホーム画面追加に対応。
- Supabase 設定後は Auth と共有 Postgres を使用し、RLS でドライバー / 管理者の読み書きを制御する。アカウント作成は Supabase 管理画面、管理者ロール変更は SQL Editor で行う。
- Supabase 未設定時は従来のブラウザー内デモを利用する。デモデータは Supabase へ自動移行しない。
- 実運用前にバックアップ、データ保持期間、個人情報・労務データの要件を確認する。無料枠の利用上限と停止条件はサービス側の最新条件を確認する。
- 集計対象期間、運行単位での複数荷待ち記録、データ保持期間、オフライン同期方式はチームで決定する。
- 労務・個人情報に関する要件は、実運用前に関係者と確認する。
- 将来、外部AIサービスを導入する場合は、送信データ、保存期間、学習利用、委託先、利用者・組織の同意を事前に確認する。

## コードの分割

- `main.js`: 起動、画面切替、画面共通の依存を受け渡す。
- `screens/login.js`, `screens/entry.js`, `screens/records.js`, `screens/analytics.js`, `screens/admin.js`: 各画面の描画とイベント処理。
- `screens/templates/`: 画面ごとの HTML フラグメント。
- `styles/base.css`, `styles/layout.css`: 共通 CSS。`styles/screens/` に画面別 CSS。
- `shared/data.js`: 保存形式、勤務時間計算、共通データ操作。
- `shared/layout.js`, `shared/templates/shell.html`: ナビゲーションと共通 HTML シェル。

画面 HTML は `shared/templates.js` が起動時に読み込み、各画面モジュールがデータを差し込む。画面モジュールは `render...` と `bind...` を export する。担当画面以外のコードや `shared/` を変更する場合は、Pull Request で影響範囲を共有する。

## GitHub での進め方（案）

- `main` への直接 push を避け、短命な feature ブランチから Pull Request を作る。
- 3人で画面領域を分担し、共通データ形式と計算式は変更前にレビューする。担当例は README を参照。
- Pull Request では変更画面、確認手順、残課題を記載する。統合前にスマートフォン幅で確認する。
